# CAPSULES — part 1 (directions A–E) — subject: invoicepipe

## Direction A
- Premise: the product's central claim is a mathematical audit — line items, subtotal, tax and total reconcile into one figure. The page is a one-ink statement hung on a single right edge, where the amounts are stacked and each step is set larger than the last, so reading the page is reading a sum toward its total. Purpose, statuses, ingestion lines and notes attach to the same right edge as entries on a settled account.
- Fonts: display `"Helvetica Neue", Helvetica, Arial, sans-serif` (700) for `invoicepipe`; supporting `"Helvetica Neue", Helvetica, Arial, sans-serif` (400) for the two purpose lines and the action words; small `"Courier New", ui-monospace, monospace` (400/700) for the five structural labels, field list, item line, status run, ingestion lines, notes and the summation stack. Source = local system fonts only; no web font, no `@font-face`, no external file; license status = fonts as bundled with the desktop OS, not redistributed by this page; fallback status = generic `sans-serif` / `monospace` terminal keywords in every stack.
- Scale & case: name clamp(54px,13vw,164px)/0.85, tracking -0.055em; purpose clamp(19px,2.1vw,27px)/1.38; objective clamp(14px,1.3vw,17px)/1.62; field list clamp(12px,1.1vw,15px) with 0.16em tracking; summation steps clamp(16px,1.7vw,21px) → clamp(26px,3.4vw,44px) → clamp(38px,5.4vw,72px) → clamp(42px,6.6vw,96px), all 700, leading 1.08; structural labels 10px with 0.36em tracking; footer mono 12px/1.85 with 0.05em tracking; status run clamp(14px,1.5vw,19px); action words 700 clamp(15px,1.5vw,19px). Case: supplied copy kept in its own case; the five structural labels are set in literal uppercase; name lowercase. Alignment: everything right.
- Space: page padding 7vh 6vw 5vh; four blocks spread with `justify-content: space-between` and 5vh gaps; purpose block capped at 46ch and pulled to the right edge; 2.4em above each structural label; 2em above the first summation step, zero gap between steps; footer lines on 0.35em increments. The entire left field of the page stays empty — one continuous negative space roughly half the page wide.
- Color: flat canvas `#F0ECE2` on html/body; one text color `#1A1713` carrying 100% of the text — a one-color system (identity, purpose, fields, statuses, actions and notes are separated only by size, family, tracking and position).
- Signature: the right-flushed summation staircase — Subtotal, Tax, Total, Total Amount — where type size steps up with the amount, all in one bold monospace on one alignment edge.
- Invariants: single ink; single right alignment edge; the four-step order Subtotal → Tax → Total → Total Amount; sans display over mono supporting text; empty left half; all supplied lines present.
- Assumptions & risks: the staircase repeats words already inside the field list, so it must read as accumulation, not duplication; the long right-aligned objective may need manual line-break care at narrow widths; 96px Courier is heavy and may need a ceiling on large displays.
- Round 2: translate this into a one-ink statement artifact — keep the right edge and the four-step amount ladder as the layout spine, and never introduce a second text color or a left-aligned content block.

## Direction B
- Premise: the product's act is extraction — a human sentence carries the five main fields, and the system lifts them out into its own column of machine text. The page runs two registers side by side: the supplied prose in a serif on the left, the extracted record in monospace on the right, the second column starting level with the sentence the fields came from.
- Fonts: display and supporting `Georgia, "Times New Roman", serif` (700 name, 400 prose) for the left register; small `"Courier New", ui-monospace, monospace` (400) for the whole right register. Source = local system fonts; no web font, no `@font-face`, no external resource; license status = OS-bundled families, not shipped by this page; fallback status = `serif` / `monospace` generic terminals present in both stacks.
- Scale & case: name clamp(46px,9vw,116px)/0.9, tracking -0.035em; lede clamp(20px,2.2vw,27px)/1.4 justified with hyphenation; objective 17px/1.62 justified with hyphenation; drop instruction clamp(24px,3vw,38px) 700; queue line 17px/1.5; action words 16px 700; right register 13px/1.7 with 0.03em tracking, individual field entries 16px with 0.1em tracking, status run 15px, structural labels 10px with 0.32em tracking in literal uppercase. Case: supplied copy unchanged apart from the uppercase structural labels; the field list is broken one entry per line, order preserved.
- Space: page padding 8vh 6vw 7vh; CSS grid `minmax(0,54ch)` prose column plus `minmax(11rem,21rem)` machine column, gap 4.5rem/6vw, both columns top-aligned in the same row beneath a name that spans the full width; 2.4em above structural labels (first label of each column set flush to the row top); 1.8em before the drop instruction, 2.2em before the action words; right column lines on 0.45em increments; outer right margin left as air.
- Color: flat canvas `#F7F5EF`; primary `#15161B` on the left register (name, purpose, instructions, action words) ≈ 55% of the text; secondary `#4B5A64` on the right register (field entries, item line, verdict, status run, constraints, notes) ≈ 45%. Two-color system, one job per ink: human language left, machine record right.
- Signature: the monospace extraction column standing level with the prose that names the fields, so each supplied field entry sits beside the sentence it was pulled out of.
- Invariants: two inks mapped exactly to two registers; serif/monospace pairing; the two-column row structure under a full-width name; the field list broken one entry per line in supplied order; justified, hyphenated prose.
- Assumptions & risks: column heights are unequal and the page bottom may finish unevenly; the alignment claim depends on both columns starting at the same grid row — if the name is later split, the pairing breaks; Georgia justified at 54ch can produce loose lines without hyphenation support.
- Round 2: build the review artifact as a two-register spread — source prose in serif on the left, extracted values in monospace on the right, top-aligned to the sentence, and do not merge the registers or add a third color.

The audit sentence runs vertically down the right edge, because the pipeline reads while the queue is still empty.

## Direction D

The page steps those voices across the page: identity flush left, the human record indented, the machine record indented further, the state vocabulary deepest of all, with each deeper step re-inked by the kind of statement it is, and the status words carrying settled states and exceptions in their own inks.

## Direction E
- Premise: duplicate invoice detection exists to stop a second payment on a matching invoice number. The page performs that check in type: the record block is printed once as the invoice in hand, then captioned, then printed again — identical in every typographic respect, offset to the right and re-inked — as the historical match found in the database.
- Fonts: single family `"Times New Roman", Times, serif` for every element — name (700), purpose lines (400), record entries (400), action words (700), caption (700), structural labels (400, uppercase, tracked). Source = local system font; no web font, no `@font-face`, no external resource; license status = OS-bundled family; fallback status = generic `serif` terminal keyword.
- Scale & case: name clamp(48px,10vw,132px)/0.9, tracking -0.01em; narrative clamp(17px,1.8vw,22px)/1.5 capped 56ch; objective line clamp(15px,1.5vw,18px)/1.6 capped 60ch; record entries clamp(15px,1.6vw,19px)/1.75 with the status run at 0.05em tracking; action words 700 with 0.04em tracking; caption clamp(13px,1.3vw,16px) 700 with 0.3em tracking; tail lines clamp(15px,1.5vw,18px)/1.7 capped 54ch; structural labels 11px with 0.3em tracking, literal uppercase. Case: supplied copy unchanged apart from the uppercase labels; repetition of the record block is verbatim.
- Space: page padding 9vh 8vw; header at the top, then a 13vh interval before the record block, 6.5vh before the caption, 6.5vh before the duplicate block, and 13vh before the tail lines; the duplicate block alone carries `margin-left: 10ch`; record and tail blocks capped at 54–60ch leaving the right third of the page open throughout; no other indent on the page.
- Color: flat canvas `#FFFFFF`; primary `#14161C` for the record in hand and all narrative, instructions and notes ≈ 60% of the text; secondary `#3F5C82` for the matched historical record, which is the entire duplicate block ≈ 40%. Two-color system, one job per ink: original and match.
- Signature: the record block appearing twice with identical type — the second copy shifted 10ch right and set wholly in the match ink, sitting directly under the caption Duplicate Invoice Detection.
- Invariants: single serif family; two inks separated by job, never mixed inside a block; the 10ch offset between the two copies; the caption between them; one verbatim duplicate of the record block; the open right margin.
- Assumptions & risks: the duplicate block doubles part of the copy, so page length grows — if a later artifact needs a shorter page, drop lines from both copies, never from one; without the caption the offset could read as a layout accident; pure white plus a cool secondary may read flatter than the other directions and may need denser record copy rather than a third color.
- Round 2: render the duplicate check as two matching record panels in type — identical sizes and spacing, the second offset and re-inked with the caption between them, and never differentiate the copies with rules, boxes or a third color.
